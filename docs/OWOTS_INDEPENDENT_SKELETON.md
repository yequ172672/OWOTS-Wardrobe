# 服装系统独立骨架（测试候选）

2026-09-18 转换器修订：如果独立 93 关节 FBXSKEL 只有旋转不匹配、名称/层级/缩放仍匹配，
且所选部位没有直接引用它，自动不发布该 rig，改用 BODY mesh 内嵌休止数据。
清单省略 `resource` 和 `bindPositions`，现有运行时从 BODY 读取休止位置。
报告记录源 SHA-256、变化关节和 `ACTOR_SKELETON_ROTATION_MESH_FALLBACK`，提示需要测试。
这条路径不修改源模型，不导入 rig 旋转，也不覆盖原始 `/90`。

## 使用方式

独立骨架是身体服装清单的可选能力。转换器读取服装自带身体网格的骨架休止姿态，
把"相对原版根骨架的每关节位移"写进 `manifest.json` 的 `skeleton` 声明；运行时在
游戏线程把这段位移作为关节重基偏移施加到角色根骨架，使动画叠加在作者体型之上。

不要求每件服装安装自己的 Lua，不携带私有骨架资源，也不覆盖原版 `player.pfb` 或
公共骨架路径。因此多套服装各自的体型不会互相抢同一个骨架文件。

本测试版首次启动默认只读诊断，并写出关节探针结果供核对。基线确认后，在
REFramework 中勾选 `Enable wardrobe independent skeletons`，系统会
记住设置（该设置同样写入 `mode`）；以后穿戴声明了独立骨架的身体服装会自动触发切换。普通服装没有此声明，
维持原有行为。取消或更换服装时停止写入并恢复。资源路径或偏移写入成功不等于体型
生效；验收必须同时确认关节构建、位置与实际画面。

## 为什么不需要替换骨架资源

2026-09-16 实机只读探针（PID 40752）确认：

- 角色根 transform 是 **93 关节**，休止姿态为**原厂 stock**；
- BODY 件自带 **461 关节**骨架，其 `get_BaseLocalPosition` 就是**作者写的 2B 休止姿态**
  （与离线 mesh 审计逐位一致）；
- 所有同名关节 `root.world == body.world`，身体被约束同步到根；
- 身体件带有 `via.motion.JointConstraints`、`via.motion.Chain2`、`via.motion.ChildSecondary`。

即体型数据本来就在身体网格骨架里；运行时之所以回 stock，是因为身体被强制用根的
（原厂）世界姿态蒙皮。正确做法是把动画重基到作者休止姿态，而不是换掉根骨架资源
（换句柄会触发原生重建，已在 PID 66060 崩溃）。

## 首版能力边界

- `actor-fbxskel-v1` 只在**根 Motion 骨架同拓扑**（原版 93 关节、名称、顺序、父子层级）
  的条件下工作：只调整已存在关节的休止位移，不新增/替换根 Motion 驱动关节，也不重定向动画。
- **物理骨骼不在此限制内。** 布料/头发/挂件等物理链走 `chain2`/cloth，辅助骨走关节约束
  （`.jcns`）。它们是独立于根 93 关节层的数据，由服装包自己的 part PFB / 约束资源携带，
  不受"同拓扑"约束，也不会与根骨架冲突。
- 转换器只处理能够验证的休止位移；无法验证的语义不猜测。
- 2B 的独立骨架属于本轮目标。Scarlet 的 264 关节角色骨架、追加角色组件和特殊动画逻辑
  不属于这个契约；不能通过改数字或跳过验证伪装成普通服装。
- 旧服装包不会凭空获得骨架支持：需用新转换器重新导出，携带 `skeleton` 声明。
- 这是待实机验收的候选。离线解析、模拟 SDK 和编译通过不证明已经解决视觉体型或所有换装场景。

## 清单字段

schemaVersion 2 的身体服装可增加以下对象，所有资源路径均不带磁盘数字版本后缀：

```json
{
  "skeleton": {
    "schemaVersion": 1,
    "kind": "actor-fbxskel-v1",
    "bodyMesh": "mods/example_body/body.mesh",
    "baselineResource": "art/model/character/ch0/ch001_00/90/ch001_00_90.fbxskel",
    "jointNames": ["由转换器写入全部 93 个有序名称"],
    "bindPositions": {"由转换器写入每个关节的作者休止局部位置": [0, 0, 0]}
  }
}
```

- `bodyMesh` 指向作者身体网格，用于运行时定位并读取其骨架。
- `bindPositions` 是**作者身体骨架的休止局部位置**（绝对量），**可选**：
  - 有它 → 运行时以它为准（Δ = `bindPositions[name] − 原版根骨架休止`）；
  - 没有它 → 运行时读**当前生效身体件 mesh 内嵌骨架**的休止（兼容路径）。
- `resource`（私有 `/90` 路径）**可选且运行时不再使用**。mod 自带的 `/90` **绝不能**放到游戏
  根骨架路径（会全局覆盖、和按服装切换冲突）；留在私有目录不加载，或不打包。
- 兼容契约（转换器侧）：转换时判断作者把体型写在 mesh 内嵌骨架还是独立骨架文件里；
  - 写在独立骨架文件 → 把休止写入 `bindPositions`（生成/更新 manifest）；
  - 写在 mesh 里 → 可省略 `bindPositions`，运行时按 mesh 读取。
  两条路径都由同一个运行时处理，不需要为不同来源维护两套逻辑。

示意中的关节占位符不是可安装配置。解析器检查完整性、有限坐标、重复名称、所属类别和
私有目录边界。运行时再次核对实际身体网格、角色身份、组件所有权和骨架基线。

## 运行时写入约定（已实机确认）

由两次只读探针与实机写入验证（`_validation/owots-joint-rebase-probe-20260916/`）定稿：

- 重基偏移写**根关节**，不写身体关节。实机 300/300 帧确认 `root.world == body.world`，
  身体每帧跟随根；身体侧携带 `JointConstraints`/`Chain2`/`ChildSecondary`，直接写身体会被覆盖。
- 写入值取 `rootRest + Δ`，Δ = `bodyRest − rootRest`（运行时从实际生效身体件的
  `get_BaseLocalPosition` 与根骨架求差）。2B 的差异是纯平移、动画主要是旋转，因此位置重基
  不干扰肢体动画。撤销时写回 `rootRest`。
- **必须在 `re.on_application_entry("UpdateMotion", …)` 阶段写。** 在 `UpdateBehavior` 阶段写实测
  无效（值写入并读回一致，但画面不变）；`UpdateMotion` 阶段写入实测成功。
- `get_LocalPosition` 返回存储量（休止/偏移），不是当前动画量；它可用于写入后的回读校验，
  但不能用来判断画面。
- 本方案只改根 93 关节的局部位置，不创建资源、不持有 holder、不触碰原生重建路径。

## 从旧 2B 测试补丁升级

完整退出游戏后使用发行包安装脚本。系统包会通过带备份的安装事务把旧
`yorha_2b_skeleton_adapter.lua` 替换为不执行操作的兼容标记，同时安装通用控制器。
已有服装模型和其他 MOD 保留。安装后完整启动游戏，禁止以热重载或脚本重置代替重启。

升级前安装器备份可用于退出游戏后的回滚。新的通用控制器检测到旧控制器仍在同一 Lua
环境时会阻止绑定，避免两个控制器争用角色骨架。

## 实机验收

模式设置保存在 `reframework/data/owots-wardrobe-skeleton-config.json`，内容为
`{"mode":"diagnostic"}` 或 `{"mode":"apply"}`。状态位于
`reframework/data/owots-wardrobe-skeleton-status.json`，关节探针另有
`owots-joint-probe.json` / `owots-joint-probe2.json`。UI 只排队改变模式，实际写入或恢复
由游戏线程处理。

1. 使用只读诊断模式确认当前服装、原版骨架路径、93 关节、身体骨架 461 关节及构建状态。
2. 启用后检查独立骨架位置及可见体型；同时检查动作、头发和附件跟随。
3. 切换两个独立骨架服装、切回普通服装，并检查暂停恢复、读档和场景切换。
4. 出现未恢复或脚本重置状态时退出游戏；不要通过重新加载脚本强行继续。

通用控制器属于系统发布物；第三方 MOD 脚本、作者 loader、原始游戏资源和存档不会进入系统发行包。
