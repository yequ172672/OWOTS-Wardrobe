# 鬼武者 Mod 转换器

把常规替换 Mod 转为服装系统可用的独立外观。

## 使用

1. 解压程序，保持 EXE 和 `OWOTS_STM_Release.list` 在一起。
2. 打开 EXE，选择游戏目录。输出目录可留空，默认保存到每个输入 Mod 旁边。
3. 把 Mod 文件夹、ZIP、RAR、7z 或普通 PAK 拖入窗口。
4. 转换完成后生成 `原名称-衣橱.zip`，点击“打开位置”找到压缩包。解压后把其中的 `natives` 和 `reframework` 文件夹合并到游戏目录。

程序记住目录设置，可以连续拖入多个 Mod。转换不会修改原 Mod 或游戏文件，也不会覆盖已有结果。
支持一次拖入多个文件或文件夹，也可以在转换中继续追加。每个 Mod 独立生成 ZIP；其中一个失败不会中止其他 Mod。
设置输出目录时，所有结果统一保存到该目录；清空后恢复跟随输入位置。同名结果自动加编号。
压缩包保留转换清单和问题报告，打包取消或失败不会留下半成品。

结果会列出实际生成的服装、披风、护手和武器。身体可以默认带上配套披风和护手；穿戴后仍可另选附件。使用这种配套穿戴需要支持 schema 3 的新版服装系统。

同一套外观被复制到多个原生服装位置时，会合并为一个条目。不同模型、配色或配套附件会分别保留；合并的原生目标记录在报告中。

只有发生问题时才需要查看原因。包含脚本、插件或无法识别的资源时，会提示哪些内容没有转换。转换结果的报告保留详细文件清单。

## 支持范围

- 常见的完整角色、多部位、多服装和多武器替换。
- 纯纹理、部分材质或局部模型替换；未修改的部分继续引用原版资源。
- 可确认的极小占位部件改为声明隐藏；无法确认时保留作者的模型。
- 单独骨架只有旋转与原版不同时，使用 BODY 模型内的体型数据继续转换，结果提示需要测试。
- 模型及其可识别的附属资源。扩展角色骨架、脚本逻辑和动态功能不会被强行改造成服装配置。

转换只整理资源、改写必要路径并生成配置，不判断原 Mod 本身能否正常运行。

Windows x64，需要 .NET 10 x64 Runtime。发行 EXE 自带 Python 和解压组件，不需要 Blender。RAR 的读取组件来自 7-Zip，许可和来源保留在发行包内。

## 源码与验证

Python 3.11+：安装 `requirements.txt` 后运行 `python converter_gui.py`。
无窗口启动检查：`python converter_gui.py --self-test`。

旧的单条目命令行接口保留在 `mod_converter.py`，也可通过 EXE 的 `--cli` 前缀调用。它的显式部位计划和实验选项仅供原有自动化流程使用，普通窗口使用新的批量转换服务。

```powershell
python -m unittest discover -s tests
python converter_gui.py --self-test
python build_release.py --output D:\builds\owots-converter-new
```

开发构建需要先准备 `runtime/`。`prepare_dependencies.py` 提供结构化 catalog 读写组件；`prepare_archive_tools.py` 从官方 7-Zip 26.03 文件中验证并收集 RAR 读取组件。原始游戏资源和测试 Mod 不进入发行包。
`--output` 是构建中间目录；最终发行 ZIP 和校验文件默认写入项目根目录的 `release/`，该目录不进入 Git。需要另放发行包时可指定 `--release-dir`。
