## dev4：重复替换目标合并

同一外观复制到多个原生服装位置时，按实际资源内容合并注册，优先保留普通版本。
这次只改转换器，不改变服装系统的声明穿戴或手动附件覆盖规则。

- 新的比较模块核对完整模型、材质属性与纹理槽、实际 base/streaming 纹理、附属资产，
  同时比较提供的部位、隐藏规则和配套披风/护手。不同配色、模型、材质或附件组合保留。
- PFB 比较保留对象/类型/引用表、CRC 和未知字段。跨普通/HQ 的合并先核对原版模板结构；
  只将原版技能行、无引用的旧路径字符串、已证明不可见的附加模型视为上下文差异。
  自定义字段变化走严格比较，无法确认时保留条目；不按名称或文件大小猜测。
- 原版同一目标族的 AC/HQ 未增加作者资源时，仍视为同一个替换方案，单独记录此种合并依据。
  不把这个规则扩大为任意原版材质相等，也不跨独立资源层合并。
- 披风和护手先合并，再核对身体的声明穿戴结果；保留覆盖的角色族，避免合并后丢失配套关联。
- 报告记录 `coveredTargets`、`duplicateEvidence` 和资源的 `duplicate-appearance / representedBy`。
  合并掉的重复资源不会再被当作未识别资源；真正不在服装范围内的资源继续提示。

75 项回归测试与源码、独立 EXE 的窗口自检通过。新增检查覆盖跨路径复制、模型/配色/材质槽差异、
高清纹理差异、原版未修改模型、PFB 字段/资源槽顺序、HQ 可见附加模型、隐藏规则、附件组合及取消。

## 已实现

- 普通用户窗口仅保留游戏/输出目录、拖入区和结果。支持文件夹、PAK、ZIP、RAR、7z，记住目录，可取消任务；实际问题才显示原因。
- 自动识别多个资源根和嵌套包，沿 Mod 覆盖原版后的依赖图识别部位，包括纯纹理与局部替换。未修改资源保留原版引用。
- BODY、HEAD、HAIR 按目标组合；可见披风和护手独立注册。schema 3 的 `rules.equip` 声明默认附件，之后手动选择可覆盖。取消或更换身体只撤回未被用户覆盖的默认附件。
- 多武器按实际原生 ID 分组，多个身体目标分别注册；AC/HQ 未增加作者资源时记录为覆盖目标，有额外资源则保留条目。
- 使用各 LOD 的索引和几何范围判断极小占位，成功时声明隐藏；不确定时保留作者模型。不是按文件大小或骨骼数猜测。
- PFB/普通 USER 只改写经过定位、长度不变的路径，并核对其他字节完全不变。catalog 仍使用结构化读取、选行和回读。
- 原 Mod 和游戏只读，输出目录不覆盖；结果列出生成条目、资源去向和未转换内容。不读取测试 Mod 的描述、文档或脚本内容，不执行附带程序。

用户确认 `OniSwordModXiaoShen` 曾按 AI-START 的 BODY mesh 内嵌休止路径成功使用。

不导入该 rig 的旋转或绑定位置，不覆盖原始 `/90`。报告保留源哈希、变化关节和
`ACTOR_SKELETON_ROTATION_MESH_FALLBACK`；窗口提示需要测试。扩展拓扑和脚本功能仍不在自动转换范围。
