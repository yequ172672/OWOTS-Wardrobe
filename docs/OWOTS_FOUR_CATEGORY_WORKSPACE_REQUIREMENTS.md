# 四分类外观与服装工程需求

状态：用户已授权开发；2026-09-15。本文补充既有需求，不取消既有共存、实际装备分离、图片预览、存档关联和生命周期要求。

## 用户行为

菜单提供身体、披风、护手、武器四类，各保存一个用户选择。身体条目可包含 BODY/BODY_SUB/HEAD/HAIR；披风对应 CLOAK，护手对应 GAUNTLET，武器包含武器、鞘等已有武器部位。分类不是原生数字枚举。

分别维护“期望选择”和“实际生效组合”。声明冲突只抑制实际显示，不删除期望选择；解除冲突后自动恢复。例如身体 B 不兼容披风，披风 A 暂时隐藏，换回兼容身体后 A 恢复。UI 标明抑制原因，存档记录期望选择。

缺失的部位默认继承原生，不等于隐藏。作者可显式声明隐藏 HEAD/HAIR 等部位，以及不兼容的外观类别。被声明不兼容的类别包括该类别的原生显示，不能取消 MOD 后又显示原生披风。隐藏与不加载是不同的引擎实现，先验证能力；不支持时在预检中拒绝应用并说明原因，不静默忽略声明。

首版冲突裁决采用固定优先级：身体、披风、护手、武器。任一方声明与另一类别不兼容，低优先级类别被抑制；规则由已生效条目施加，被抑制或缺失条目不再施加规则。禁止条目隐藏自身提供的部位。任何冲突计算都不能改实际武器属性。

## Mesh 插件工程流程

1. 原生索引预置游戏/类别/条目/部位与资源关联，不随插件分发游戏资产。索引数据必须来自解析结果并携带来源版本，不凭文件命名猜关联。
2. 作者选择身体、披风、护手或武器，一键读取本机原始资源及对应 PFB/必要配置。一个 Mesh 对应多个模板时要求明确选择；缺失依赖明确报告。
3. 保存原路径、实际版本、源 SHA256、稳定资产 ID 与已有 exporter 基线。编辑、重命名、发布不重设源基线。
4. 常用面板编辑显示信息、部位集合、资源引用、隐藏/冲突声明。高级 PFB 字段按经过往返验证的能力逐步开放；未知字段和对象引用保留。
5. 保留替换式导出；新增独立服装包导出，产生对应类别的 manifest 和必要独立资源。
6. “只导出修改项”指避免重复导出无变化资源；首包仍需生成独立 PFB/Catalog/MMI 等配置，及其必要私有依赖。原生共享资源不复制。路径映射或配置变化也算变化，不能只比较 Mesh。
7. 先构建依赖图与计划，再暂存、校验引用、发布；复用原有 owner/外部修改冲突与回滚机制。工作区导出不直接部署游戏。

## 协议与兼容

计划引入 schemaVersion 2，category 使用 body/cloak/gauntlet/weapon；parts 继续使用逻辑名称，rules 包含 hideParts 与 incompatibleCategories。此为下一代协议，尚未接入的消费者必须拒绝，不能让旧运行时忽略声明。

旧 schema 1 outfit 可能一次包含披风和护手，不能直接改名为 body 后丢弃这些部位。旧版运行时、manifest 和 sidecar 保留可用；迁移须显式保留完整组合及选择，不在读取时覆盖原文件。四类 UI/运行时/存档与 Mesh 导出使用同一协议后再部署。

预览仅图片；缺图使用文字占位，默认管理器图片待定。不做骨骼兼容性验证、动画重定向或武器属性注册。

## 分阶段交付与验收

- 规则层：四类选择、隐藏/冲突、固定裁决、选择保留、解除后恢复、缺失条目、无循环依赖；自动回归覆盖，尚不证明引擎隐藏能力。
- 资源层：原生索引可追溯，真实 PFB 无修改往返，依赖闭合，源哈希不变，导出增量与配置变更覆盖。
- 适配层：验证每类替换/恢复和 HEAD/HAIR/CLOAK/GAUNTLET 隐藏；暂停、CG、读档和失败清理；实际装备身份保持。
- 联调：身体合并头部并隐藏原生头发，披风/护手选择被抑制后恢复，四类存档恢复；Blender 导出包在游戏安装后实际显示正确。

原生菜单双向同步仍属既有目标；剧情锁定时先完成独立四类菜单，不宣称原生条目注册已实现。

## 2026-09-16 已知缺陷：GpuCloth（布料）
- Mesh 服装工程当前无法解析含布料数据的 PFB：模板缺正式版 `via.dynamics.GpuCloth` 序列化布局，读取在该实例处失败（`charCount ... too large`）。REE-Lib 顺序读取实例，因此整个 PFB 无法 inspect/rewrite；不能靠跳过字段或改 CRC 绕过。
- 影响范围仅限真正含布料数据的 PFB。已检查集合中，四类别里只有披风（`ch001_00_01`，普通与 HQ）受影响；身体、护手、头部、头发可正常导入。非服装文件（`player.pfb`、`ui/player_ui.pfb`）同样失败，不在四分类范围内。
- UI 与提示：披风类别标注为暂不支持并显示红色警告，其导入/导出被明确拦截并说明是 GpuCloth 缺陷；其他类别仍照常尝试导入，失败时给出同样的明确原因。
- 衣橱功能本身不读取布料字段；披风是否保留原生布料模拟（`.gpuc`）还是改由骨骼驱动，属于需要实机验收的运行时决策，组件增删也不在当前已验证的 PFB 编辑能力内。
- 解除条件：取得当前正式版的原生 RSZ/TDB 序列化定义，或完成以整文件字节往返为标准的布局重建。公有 dump 无修复版本（内置模板与上游 REasy master 逐字节相同）。详见 `RE-Mesh-Editor-main/docs/appearance-authoring.md`。
