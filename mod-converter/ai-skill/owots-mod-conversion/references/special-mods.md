# 特殊 MOD：AI 辅助专用迁移

此流程用于用户希望保留 Lua/原生插件/动作与骨骼联动等行为的情况。
普通转换器继续只负责其支持的资源处理，不为每个特殊 MOD 添加硬编码。

## 判断能迁移什么

静态阅读原脚本、配置、版本约束与资源路径，建立行为表：

| 原行为 | 触发条件/对象 | 修改的状态或资源 | 启用与撤销 | 迁移方式/验证 |
| --- | --- | --- | --- | --- |
| 例：角色布料约束 | 实际角色与模型匹配后 | 指定关节/组件 | 仅条目生效，停用恢复 | 专用生命周期适配器 |

区分外观、动态动画/骨骼、武器属性、装备/存档修改、UI 和解密加载器。
外观迁移不隐含授权改变武器数值或用户存档。相同文件名、相似模型或脚本长度都不能
证明兼容。固定 RVA/CRC 必须匹配实际游戏版本，不能把另一版本地址直接套入。

## 专用适配器的边界

- 一个完整的 v7 93 关节 FBXSKEL，如果名称顺序、父层级、旋转和缩放都与原始 `/90`
  一致，而只有绑定位置变化，可以由普通转换器写入 `manifest.skeleton`，并随 BODY mesh
  放进同一 MOD 私有目录。仍需检查实际运行时持有者和切换后的重建结果。
  新增关节、Scarlet 的 264 关节 `rig_dd`、动作/约束脚本或 Lua/native actor 扩展仍必须走专用适配；
  仅复制骨架文件或保持 mesh 字节不变不能证明这些行为已经迁移。切回普通服装时，也须验证原始骨架已恢复。
- 实机诊断应在游戏线程内同步读完并输出标量快照。不要通过后台 HTTP 反射直接调用
  游戏对象，也不要把临时组件/关节数组的裸地址留给下一次请求使用。
- 写成独立、可撤销模块，保留原作者信息。不要向通用 converter 混入某个 MOD 的脚本逻辑。
- 使用衣橱**实际生效**的条目与当前实例资源匹配控制启用。用户点击/保存的期望 ID、
  native costume ID 与动态分配的衣橱模型 ID 不是同一个概念。
- 在正确游戏线程/阶段操作。角色替换、场景切换、加载、卸载和退出选中状态时失效旧对象。
  不跨场景保留未经验证的裸指针；版本/接口无法验证时停止写入并报告。
- 仅修改自己的对象/字段。记录原值和最后写值；撤销前确认当前对象仍有效且字段仍是
  自己最后写入的值，避免覆盖其他 MOD 或游戏更新的状态。
- 武器/刀鞘/动作等涉及独立衣橱分类时，明确组合与冲突规则，不能全局强占其他选择。
- 定向复制完整动态依赖，私有化实际引用；whole-player PFB、全局 Lua 或原生 DLL
  不能未经审查原样塞进静态包。加密包只能报告有证据的解密/路径恢复范围。

专用适配器可能需要衣橱运行时提供窄的只读状态接口。优先使用公开接口，缺失时
提出明确接口契约并制作配套候选；不要猜不存在的 API 或把模拟通过说成游戏兼容。

## 验证与交付

在隔离目录完成静态检查/编译、资源闭包、启停与恢复、外部修改保留、对象替换、
重复启停、版本不匹配和分类冲突测试。模拟测试验证生命周期逻辑，不能替代真实动画、
布料、骨骼与过场观察。准备好具体候选和测试步骤，再进行用户授权范围内的游戏测试。

无法完成的部分要说明缺少的接口、格式布局、版本证据或运行环境；仍可交付已完成源码、
报告和清楚标注的候选。不把静态候选称作完整迁移，不通过关闭校验来满足成功标志。
普通打包脚本拒绝脚本/DLL；专用包使用其独立构建流程，保留审查过的代码、依赖、
版本条件、安装/卸载及恢复方案。通用 skill 不保证未知第三方 MOD 必定适配成功。
